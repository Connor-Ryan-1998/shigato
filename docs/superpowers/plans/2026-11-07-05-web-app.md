# shigoto Plan 5: Web App Foundation and First Screens

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A staff web app served from the shigoto binary. It has an app shell that modules extend, and three working screens: **Dashboard**, **Invoices** and **Reconciliation**. Staff sign in with the existing local login.

**Architecture:**
- The frontend is SvelteKit 2 with Svelte 5 runes and TypeScript, built as a static SPA (`adapter-static` with an `index.html` fallback). The build is embedded into the Go binary through a new `internal/webui` package, which serves it at `/` with SPA fallback, cache headers and a strict CSP.
- Each module has a manifest in `web/src/lib/modules/<name>/manifest.ts` declaring its nav entries, the permission each needs, and an optional dashboard card. The shell shows only the modules that `/api/v1/meta` reports as enabled and that the user's role can access.
- On the backend, each module may contribute a dashboard section through an optional `Dashboard` func on `module.Module`.

**Tech Stack:**
- Go 1.27.
- Svelte 5, `@sveltejs/kit` 2, `@sveltejs/adapter-static`, Vite, TypeScript (strict), `svelte-check`, Vitest, `@testing-library/svelte`, jsdom.
- Node 24 LTS for builds.
- No UI component library, no CSS framework and no state library.

**Spec:** `docs/design.md`, in particular these decisions: UI is "JSON API plus a JS SPA, built and embedded in the binary"; mobile is "responsive web now"; modules can be toggled. Also read `docs/superpowers/plans/2026-11-05-01-followups.md`, "Plan 5" section. Plan 6 covers OIDC, staff invites, the tenant/client portal and magic links. Login rate limiting moves to Plan 6 together with the other auth work.

## Global Constraints

- Everything from Plans 1–4 still applies on the Go side:
  - Integer cents.
  - `org_id` on every query.
  - New migrations only, with the next one `0012_`.
  - `module.WriteCoreError`.
  - Strict PUTs.
  - Audit every write.
  - Run `task lint`, `task test` and `task test SUITE=integration`.
- **Frontend dependencies:**
  - Use only the packages listed in Tech Stack.
  - Pin exact versions in `web/package.json` (no `^` or `~`) and commit `web/package-lock.json`.
  - Install with `npm ci`.
  - Pick the current stable versions at implementation time and record them in the report.
- **Money and dates:**
  - Money arrives as integer cents and is formatted only for display, with `Intl.NumberFormat('en-AU', {style:'currency', currency:'AUD'})` on `cents / 100`.
  - Money is never computed client-side. All totals come from the API.
  - Dates arrive as `YYYY-MM-DD` and are shown as `5 Nov 2026` (en-AU).
- **Styling:**
  - Plain CSS, with design tokens as CSS custom properties in `web/src/lib/styles/tokens.css`. That file holds:
    - Colours: semantic, not raw.
    - Spacing: a 4px scale.
    - Radius.
    - Type scale on the `system-ui` font stack.
    - Shadows.
  - Light and dark themes, following `prefers-color-scheme`, with a manual override saved in `localStorage` wrapped in try/catch.
  - Component styles are scoped Svelte `<style>`.
- **Layout:**
  - On wide screens, a left sidebar grouped by module plus a top bar (org switcher, user menu, theme toggle).
  - Below 768px the sidebar becomes a slide-in drawer.
  - Below 640px, data tables render as stacked cards.
  - No horizontal page scroll at 360px width.
- **Accessibility:**
  - Every input has a `<label>`.
  - Visible focus rings.
  - Fully keyboard operable: drawer and dialog trap focus and close on Esc.
  - Colour contrast is at least WCAG AA in both themes.
  - Status is never conveyed by colour alone.
- **Security:**
  - All unsafe API requests (`POST`, `PUT`, `PATCH`, `DELETE`) must send the header `X-Shigoto-CSRF: 1`. The server rejects unsafe `/api/` requests without it with 403. This works because a cross-site form cannot set custom headers.
  - If an `Origin` header is present, it must match `Config.BaseURL`'s origin.
  - `/webhooks/` is exempt.
  - The SPA is served with this CSP:
    `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`
  - Plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin`.
- **Error contract:**
  - Every API error body is `{"error": "<message>"}`, including errors from the auth middleware, which currently returns plain text.
  - The client shows `error` to the user. On 401 it redirects to `/login?next=<path>`.

## Review Focus

1. **Deep links and refresh.** Opening `/acme/invoices/42` in a fresh tab, or refreshing it, serves the SPA, and the app routes there after the session check. `/api/...` paths that don't exist still return JSON 404, never `index.html`. Test in Task 3.
2. **Disabled module.** With `SHIGOTO_MODULES=timesheets`, the Reconciliation nav entry, its routes and its dashboard card are absent. Navigating to its URL directly shows "Not found". Tests in Tasks 2 and 3.
3. **Cross-site POST.** A form post or `fetch` without `X-Shigoto-CSRF`, or with a foreign `Origin`, gets 403 and changes nothing. Webhooks still work. Test in Task 1.
4. **Session expiry mid-use.** An action that returns 401 redirects to login and comes back to the same page afterwards. Test in Task 3 (unit-test the client's redirect behaviour).
5. **Phone width.** At 360px, the dashboard, invoice list and bank-line list have no horizontal scroll, tables become cards, and the drawer opens and closes with the keyboard. This is a manual check, recorded with screenshots in the Task 6 report.
