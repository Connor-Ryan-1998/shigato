# shigoto Plan 3: Timesheets Module

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Log time against client projects, then turn unbilled time into one invoice per client per date range. Billed entries are locked. Voiding the invoice unlocks them so they can be billed again.

**Architecture:** A new `internal/timesheets` package is registered as the `timesheets` module through `internal/module`, following the pattern of `internal/property`. Billing runs create drafts with `core.CreateDraftInvoice` and can issue them through `billing.Service.Issue`. The only cross-module change is in `billing.Service.Void`, which clears the time-entry links in the same transaction.

**Tech Stack:** Go 1.27 stdlib, pgx/v5, Postgres 18.6. No new dependencies.

**Spec:** `docs/design.md`, sections Goals "Hours to invoice", Data model "Timesheets", Key flows 2.

## Global Constraints

- Everything in Plans 1 and 2 still applies:
  - Integer cents.
  - `org_id` on every query.
  - Schema changes only in new migration files. The next one is `0007_`.
  - Calendar dates stored as UTC midnight in `Config.Location`.
  - Errors go through `module.WriteCoreError`.
  - No new dependencies.
  - Use `task lint`, `task test` and `task test SUITE=integration`.
- **GST on consulting lines:**
  - If the org is GST-registered, use the project's `gst_code` (`GST` or `FRE`).
  - If the org is not registered, always use `FRE`.
- **Exact line amounts** (ruling for this plan): bill each project as one line with `QuantityMilli = 1000` and `UnitAmount = DivRound(total_minutes × hourly_rate, 60)`. Put the hours in the description. Never round minutes into milli-hours, because 50 min at $120/h must bill exactly $100.00.
- **Locking:** an entry with `invoice_line_id` set is locked. Update and delete return 409. Voiding the invoice clears the link.
- **Rates:** a billing run uses the project's *current* `hourly_rate`. There is no rate history (YAGNI).
- **Out of scope:** adding staff users. Only the owner exists today, and user management comes in Plan 5. The permissions still support staff.

## Review Focus

1. **Two billing runs for the same client and range, run at the same time.** Every entry is billed exactly once, and the second run returns `422 no unbilled time` or bills only what is left. Test in Task 3.
2. **Edit or delete of a billed entry.** Returns 409. After the invoice is voided, the entry can be edited and billed again. Test in Tasks 2 and 3.
3. **A staff user editing another user's entry.** Returns 403. Staff can read every entry in the org. Test in Task 2.
4. **Range boundaries.** `from` and `to` are inclusive dates. Entries outside the range, on other clients' projects, on inactive projects, or in another org are never picked up. Test in Task 3.
5. **Amount precision.** 50 min at $120/h gives exactly 10000. 3 entries of 20 min at $95/h gives exactly 9500. 7 min at $100/h gives `DivRound(70000, 60)` = 1167. Test in Task 3.

### Task 3: Billing runs and void unlock

**Files:**
- Create: `internal/timesheets/billrun.go`, `internal/timesheets/billrun_test.go`, `internal/timesheets/billrun_integration_test.go` (tag `integration`)
- Modify:
  - `internal/timesheets/routes.go`.
  - `internal/billing/billing.go`: in `Void`'s transaction, after `core.VoidInvoice`, run `UPDATE time_entries SET invoice_line_id = NULL WHERE org_id = $1 AND invoice_line_id IN (SELECT id FROM invoice_lines WHERE org_id = $1 AND invoice_id = $2)`.
  - `internal/billing/billing_integration_test.go`.

**Interfaces:**
- Consumes: `core.CreateDraftInvoice`, `core.NewLine` (add a `ProjectID *int64` field, persisted to `invoice_lines.project_id`, as was done for `PropertyID`), `core.GetSettings` (`GSTRegistered`), `billing.Service.Issue`, `billing.WithActor`, `core.DivRound`.
- Produces:
  - Pure, in `billrun.go`: `func LineFor(p Project, totalMinutes int, from, to time.Time, gstRegistered bool) core.NewLine`.
    - `QuantityMilli` is 1000.
    - `UnitAmount` is `DivRound(totalMinutes × HourlyRate, 60)`.
    - `GSTCode` is `p.GSTCode` when `gstRegistered`, otherwise `FRE`.
    - `ProjectID` is `&p.ID`.
    - The description is exact copy: `"<Name>: <H>h <MM>m @ $<rate as d.dd>/h (<from YYYY-MM-DD> – <to YYYY-MM-DD>)"`.
  - `type RunInput struct{ ClientContactID int64; From, To time.Time; DueInDays int; Issue bool }`.
  - `type RunResult struct{ Invoice core.Invoice; EntryCount, TotalMinutes int }`.
  - `func RunBilling(ctx context.Context, b *billing.Service, orgID int64, orgSlug string, in RunInput) (RunResult, error)`:
    1. Validate: `From <= To`, `DueInDays` between 0 and 90, and the client is a `client` contact in the org.
    2. In one transaction, select the unbilled entries of that client's projects in `[From, To]`:
       - The query is `SELECT e.id, e.project_id, e.minutes FROM time_entries e WHERE e.org_id=$1 AND e.invoice_line_id IS NULL AND e.work_date BETWEEN $2 AND $3 AND e.project_id IN (SELECT id FROM projects WHERE org_id=$1 AND client_contact_id=$4) ORDER BY e.project_id, e.id FOR UPDATE`.
       - Lock only `time_entries`. Postgres re-checks `invoice_line_id IS NULL` on rows it had to wait for.
    3. If no rows come back, return `ErrInvalidInput` with "no unbilled time".
    4. Group by project and load each project.
    5. Create the draft with `Source: "timesheet"`, one line per project ordered by project name, and the given `DueInDays`.
    6. Map each line id back to its project's entries, then `UPDATE time_entries SET invoice_line_id = <line id> WHERE org_id=$1 AND id = ANY($2)`.
    7. Commit.
    8. Then, if `Issue` is set, call `b.Issue`. A failure there returns the error, and the draft stays with its entries locked to it.
  - Route: `POST /api/v1/orgs/{org}/billing-runs` with `{client_contact_id, from, to, due_in_days, issue}`. It needs `PermInvoicesWrite`, wraps the context with `billing.WithActor(user)`, and returns `{invoice, entry_count, total_minutes}`.
