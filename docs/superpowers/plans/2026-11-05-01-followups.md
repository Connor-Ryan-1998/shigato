# Plan 1 follow-ups (carry into Plans 2–5)

These came out of the Plan 1 reviews and were deferred on purpose. Pick each one up in the plan named against it.

## Start of Plan 2 (property: rent invoices from the scheduler)
- Move issue, the QLD rule of at least 2 payment options, and send-to-provider out of `internal/httpapi/core_routes.go` into one reusable core function. The scheduler has to issue and send rent invoices without copying this logic.
- Add an org settings API covering `gst_registered`, ABN, BSB and account number, PayID and BAS frequency. Without it, the 2-payment-options rule can only be met with raw SQL.
- Stripe hardening, to do during the refactor:
  - When a webhook is matched by the metadata fallback, backfill `invoices.provider_ref` with `UPDATE ... WHERE provider_ref IS NULL`. Without this, a partially paid invoice can be sent again.
  - Pin `AutoAdvance: false` on Stripe drafts.
  - Give the detached contexts their own deadline, for example `context.WithTimeout(context.WithoutCancel(ctx), 2*time.Minute)`.
  - Add `"matched_by":"metadata"` to the audit diff when the fallback is used.
  - Compute `days_until_due` from `due_date` at send time, or use Stripe's `DueDate`, so late retries don't drift.
- Release the invoice row's `FOR UPDATE` lock before the Stripe network calls, if contention ever matters.
- Hardcoded `Australia/Brisbane` in `stripe.go` for `PaidOn`: pass `Config.Location` through `stripe.New` instead.
- `payOptionsFor` currently advertises `stripe` when only one of the two keys is set, and when there is no `provider_url`.
- Prune expired sessions from the scheduler.

## Plan 4 (recon and reports)
- Add rounding tests for negative inputs (credits and outflows). Bound inputs to `LineAmount`, which has no overflow guard.
- A `paid_at` of 0 in a webhook should fall back to the event time or today.
- An org with `gst_registered = false` still charges GST on lines coded `GST`. Enforce the flag once the settings API exists.
- Overpayments, refunds, and voiding an invoice that has partial payments (credit notes).

## Plan 5 (web and portal)
- Use one error shape everywhere. `auth` middleware still answers 401, 403 and 404 with plain-text `http.Error`.
- The portal needs query variants scoped to the contact (`Principal.ContactID`). Do not reuse the staff handlers.
- Login rate limiting, CSRF beyond `SameSite=Lax`, and Content-Type checks.
- List responses return `"lines": []`. Either omit the field or load the lines.

## Housekeeping (any time)
- `Config.Stripe` is never populated; delete the field.
- A trailing comma in `SHIGOTO_MODULES` gives `unknown module ""`.
- The dev DSN is duplicated in `docker-compose.yml` and `Taskfile.yml`.
- `admin create-owner` has three problems:
  - It trims spaces from the password.
  - It prints "owner ready" even when the existing membership is not an owner.
  - Its steps don't run in one transaction.
- `listInvoices` queries the org once per invoice (N+1) for payment options.
- `dummyHash` is computed at startup (about 250 ms). The advisory unlock error in `Migrate` is discarded.
- On TLS-intercepted machines, `docker compose up --build` needs the `laptop_ca` build secret. Document this in the README.
- The Fake writes `slog` noise in send-failure tests. Add webhook tests for an org that has no provider configured.
