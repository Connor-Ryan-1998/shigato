- **`PUT /settings` replaces the whole record:** a client that omits a field resets it. Plan 5's UI must send the full object, or move to PATCH.
- **Test gaps:**
  - The scheduler's close-connection-on-unlock-failure path has no test.

  - `asOfDate` has no test for a non-UTC timezone.
  - The bond branch "issue fails, then 409" has no test.

  - `LodgeBond` duplicates `BondInfo`.

- **Audit diff:** settings audit entries store BSB, account number and PayID in plaintext. Redact them in Plan 5.

## Plan 3 leftovers
- **Rate-pointer conversion duplicated:** `task.hourly_rate`/`project.hourly_rate` pointer-to-`core.Cents` conversion is repeated across timesheets' routes and task/project code instead of one shared helper.
- **`checkTaskForEntry`'s `GetProject` error is unmapped:** a non-`ErrNotFound` error from `GetProject` is returned as-is rather than wrapped, and is currently unreachable (a task's `project_id` always references a real row), so it's untested.
- **`TestVoidUnlocksEntries` placement:** it lives in `billrun_integration_test.go` but tests `billing.Void`/entry unlocking, not a billing run; a `TestVoidUnlocksEntriesFromDraft` sibling was added in the same file for consistency, but both arguably belong nearer the entries/billing void tests.
- **`dateLayout` duplicated** across `billing`, `httpapi` and `timesheets` (each has its own `"2006-01-02"` constant).
- **Weak billing-run concurrency test:** `TestRunBillingConcurrent` has no barrier forcing the two goroutines' transactions to actually overlap; it exercises the locking code path but doesn't reliably prove the race is closed.
- **No index on `time_entries.invoice_line_id`** (billing-run void unlocking and billed-entry lookups scan it), and **no FK tying `time_entries.org_id` to its task's org** - `time_entries.org_id` does have a plain `REFERENCES orgs`, but nothing stops it disagreeing with `project_tasks.org_id` for the same `task_id` (no composite FK, unlike the checks `checkTaskForEntry` does in application code).
- **Staff can't manage projects/tasks:** `auth.PermTimesheetsAdmin` is owner-only today; revisit once Plan 5 adds staff users with a role that should hold it.

## Later
- **Credit notes, refunds and overpayment handling.** `billing.Void` now refuses an invoice with any recorded payment (409, "invoice has payments; record a credit note instead"), closing the double-billing risk, but there's still no way to actually issue a credit note, process a refund, or record an overpayment.
- **Voided middle periods:** a voided rent period with live periods after it is not re-billed automatically; only trailing voids are. Gap-filling belongs in `PeriodsToInvoice`.
- **Edits inside billed periods:** rent changes, charges and terminations dated inside an already-invoiced period are silently ignored. They should warn instead.

## Plan 5 (web and portal)
- Use one error shape everywhere. `auth` middleware still answers 401, 403 and 404 with plain-text `http.Error`.
- The portal needs query variants scoped to the contact (`Principal.ContactID`). Do not reuse the staff handlers.
- Login rate limiting, CSRF beyond `SameSite=Lax`, and Content-Type checks.
- List responses return `"lines": []`. Either omit the field or load the lines.
