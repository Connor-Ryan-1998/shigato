## Plan 2 leftovers
- **Voided middle periods:** a voided rent period with live periods after it is not re-billed automatically; only trailing voids are. Gap-filling belongs in `PeriodsToInvoice`. Do this with the Plan 4 credits work.
- **Edits inside billed periods:** rent changes, charges and terminations dated inside an already-invoiced period are silently ignored. They should warn, and credits come in Plan 4.
- **Late-issued invoices:** an invoice issued after its due date gets `due_date = issue date`, so it counts as arrears from the next day.
- **`PUT /settings` replaces the whole record:** a client that omits a field resets it. Plan 5's UI must send the full object, or move to PATCH.
- **Test gaps:**
  - The scheduler's close-connection-on-unlock-failure path has no test.
  - The log line for a tenantless lease has no test.
  - `asOfDate` has no test for a non-UTC timezone.
  - The bond branch "issue fails, then 409" has no test.
- **Code hygiene:**
  - `runInTx` is duplicated in `billing` and `module`.
  - Optional-date parsing is repeated in `property/routes.go`.
  - `LodgeBond` duplicates `BondInfo`.
  - `clockNow` is restored with `defer` instead of `t.Cleanup`.
  - `listOrgs` takes the pool instead of `core.Querier`.
  - Stripe test hygiene items from the Task 2 review are still open.
- **Audit diff:** settings audit entries store BSB, account number and PayID in plaintext. Redact them in Plan 5.

## Plan 4 (recon and reports)
- Add rounding tests for negative inputs (credits and outflows). Bound inputs to `LineAmount`, which has no overflow guard.
- A `paid_at` of 0 in a webhook should fall back to the event time or today.
- An org with `gst_registered = false` still charges GST on lines coded `GST`. Enforce the flag once the settings API exists.
- Overpayments, refunds, and voiding an invoice that has partial payments (credit notes).

## Plan 5 (web and portal)
- Use one error shape everywhere. `auth` middleware still answers 401, 403 and 404 with plain-text `http.Error`.
- The portal needs query variants scoped to the contact (`Principal.ContactID`). Do not reuse the staff handlers.
- Login rate limiting, CSRF beyond `SameSite=Lax`, and Content-Type checks.
- List responses return `"lines": []`. Either omit the field or load the lines.
